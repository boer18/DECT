# 表格工具

源码仓库：https://github.com/boer18/DECT

下载应用：[GitHub Releases](https://github.com/boer18/DECT/releases)。下载 ZIP 后解压，将「表格工具.app」拖到「应用程序」，再拖入程序坞。适用于 Apple Silicon Mac，macOS 14 或更新版本。当前为本地签名版本，未经过 Apple 公证；首次启动如被系统拦截，请在系统设置的「隐私与安全性」中确认来源后允许打开。

仓库不包含工程配置表、API Key 或本机工作区缓存。翻译功能需要在应用内配置自己的 API，或读取本机已有的 TCST 工具设置。

一个面向 Unity 配置表工作流的原生 macOS 本地工具。它把多项目扫描、配置表浏览与编辑、多表并排、多语言处理、版本前后表格对比和一键导表集中到同一个工作区中。

工具不要求为了导表而打开 Unity：导表时直接调用对应工程已有的 `Config/gen.sh`，脚本的标准输出、错误输出和退出状态都会回到工具界面。

## 适用场景

- `Project` 目录下同时维护多个工程，需要快速切换项目并导出指定工程的表。
- 双线或多线开发时，需要同时查看不同项目中同名的配置表，并在表格之间复制部分单元格、行或列。
- 不想为打开一张表而层层进入工程目录，或者不想反复启动 Unity 只为了导表。
- 版本上线前，需要比较历史版本和当前版本文件夹中的全部配置表，而不只是查看几个手工挑选的文件。
- 需要批量补齐 `TbLanguage` 缺失翻译，并在保存后直接导表。

| 模块 | 能力 | 主要用途 |

| 多表工作区 | 多表并排、多个标签、同名表并存、表间复制粘贴 | 对照不同项目或不同版本的表格 |

## 日常使用

### 1. 选择项目根目录并切换工程

首次使用时选择保存工程的 `Project` 目录。工具会识别该目录下的工程，也支持识别二级目录中的工程；之后启动会优先使用已保存的项目路径和工程清单，减少每次打开时的完整扫描时间。

顶部项目 Tab 是整个工作区的入口。切换项目后，配置表、多语言表和导表日志都会跟随当前项目，不需要重新打开 Unity 或手动进入多层文件夹。

### 2. 浏览和编辑配置表

配置表列表位于工作区左侧：

- 支持按表名或路径搜索，也可以收藏常用表并只查看收藏。
- 列表使用稳定的正常配色和路径顺序，不会根据打开次数改变颜色或排序。
- 左侧列表为白底，便于和表格内容区分。
- 单击表格时，在关闭多表并排的情况下复用当前预览标签；已有未保存内容不会被下一张表静默覆盖。
- 双击表格可以使用系统默认表格应用打开原文件。
- 双击表格中的单元格会进入单元格内编辑，按 `Enter` 提交；也可以使用上方的内容输入框修改当前单元格。
- 通过「添加表格」可以主动保留多个标签，也可以加入项目内其他路径或外部表格。
- 标签可以单独关闭；关闭有未保存修改的表格时会先提示保存。

表格编辑区支持：

- 双击单元格或按 `Enter` 编辑单元格。
- 拖选或使用 `Shift` 选择矩形区域。
- 点击行号选择整行，点击列字母选择整列；连续选择后可以复制整行或整列。
- `⌘C` 复制，`⌘V` 从当前选区左上角粘贴；复制内容来自实际数据范围，不会把表格末尾的空白扩展区域一并复制。
- 支持 Excel 常见的右下角填充柄：选中一个单元格或矩形区域后，拖动选区右下角的小方块即可向下或向右填充。普通文本和已有模式会重复复制；连续数字、日期会按步长延续；公式会按相对行列自动调整，绝对引用保持不变。单次填充最多 50,000 个单元格，可用撤销恢复。
- 撤销、重做、单表保存，以及「保存并导表」。
- 冻结指定数量的行和列。输入前 N 行、前 N 列即可固定表头或关键字段，填 `0` 表示不冻结；冻结只影响工具内视图，不会修改 Excel 文件的冻结设置。
- 外部文件变化检测。没有未保存编辑时会自动刷新；有未保存编辑时会保留本地内容并提示冲突，不会静默覆盖正在编辑的内容。
- 编辑范围覆盖前 256 列；单次粘贴最多 50,000 个单元格。
- 公式单元格未选中时显示工作簿保存的计算结果，选中时在当前格和顶部输入框显示原始公式，可双击修改。工具不提供公式计算引擎；修改公式后需使用支持该公式的表格应用重新计算，不能保证导表脚本会自动计算。复制时复制公式内容。
- 配置表支持 50%～250% 缩放：使用工具栏的 `− / +` 和「重置大小」、触控板捏合，或按住 `⌘ / Control` 滚轮。缩放只影响视图。
- 配置表工具栏新增「自适应」菜单：可一键适配行高与列宽、单独适配列宽，或开关自动换行。列宽按表头及全表均匀抽样的内容估算，取 90% 分位并限制在 90～300 点；自动行高限制在 29～96 点，避免少量超长内容撑坏布局。仍可手动拖动列宽，也可恢复默认行高与列宽。默认保持紧凑布局，按需开启；仅影响当前视图，不修改 Excel 的格式或内容。
- 超长单元格可通过内容栏右侧的展开按钮查看完整内容、选中文字或复制全文；展开窗口只读，编辑仍在单元格或内容栏进行。公式单元格在展开窗口显示完整原始公式。

工具内编辑主要面向 `XLSX`。`XLS`、`XLSM` 和 `CSV` 可以通过系统默认应用打开；它们也可以参与表格对比，但不代表都能在工具内以相同方式编辑。

保存时只写入实际修改的内容，并尽量保留工作簿的其他部件。工具不会自动生成源表备份，这是当前产品行为；如果需要历史副本，应在执行保存前自行准备副本。

### 3. 多表并排和同名表处理

「多表并排」默认关闭。关闭时只有当前预览表格，不会给整张单表套蓝色选中框；顶部标签用于切换已打开的表格。打开「多表并排」后，可以在右侧持续添加表格并自由增加并排表的数量，当前激活的表格面板会用蓝色描边标记，其他面板保持普通状态。表格之间通过完整路径区分，因此不同项目中同名的 `.xlsx` 可以同时打开。

点击并排模式中的某个表格单元格或列头，会将该表格设为当前激活表。无论是并排模式还是标签模式，表格都支持编辑、复制粘贴、保存和外部修改刷新。

典型的跨项目配置迁移流程如下：

1. 在当前项目 Tab 中打开第一张表。
2. 使用「添加表格」打开另一个项目中的同名表，或开启多表并排。
3. 选中需要迁移的单元格、行或列并复制。
4. 在目标表中选中起始位置粘贴，检查内容后保存目标表。

这里复制的是表格中的内容，不是直接覆盖整个表文件，因此不会因为同名表而丢失另一份工程的配置。

### 4. 一键导表和错误日志

当前项目右上角提供导表入口，也支持快捷键 `⌘Return`。执行导表前，工具会先处理当前项目在工具内的修改，再运行该工程的：

```text
<项目目录>/Config/gen.sh
```

导表窗口会实时显示：

- 当前工程名称和工程目录；
- 实际执行的脚本路径；
- 脚本标准输出和错误输出；
- 成功或失败状态；
- 失败时的退出代码。

因此，像 `dotnet`、Luban、脚本路径或权限缺失等问题，会把脚本返回的具体错误直接显示在日志中，而不是只显示一个笼统的“导表失败”。日志支持复制，也支持自动跟随最新输出。

导表功能不启动 Unity，也不负责修复工程自身的脚本依赖；如果 `gen.sh` 本身缺少命令、DLL 或执行权限，需要根据日志修复对应工程环境。

### 5. 多语言工具

多语言工具面向各项目的 `TbLanguage` 表。它会读取工作簿中的语言列和文本内容，并在当前项目工作区内处理译文。

顶部提供以下操作：

- 翻译全部缺失：只处理当前工程中尚未填写的多语言内容。
- 保存全部：将当前语言表工作区中的修改写回文件。
- 翻译并导表：完成翻译后直接执行保存和导表流程。
- 保存并导表：不翻译，只保存当前语言表修改并导表。
- AI 一致性检查：让配置的翻译服务检查每条译文是否与原文含义一致，并返回需要复核的项目。
- 全部、缺失、已修改筛选：只改变浏览范围，不会改变全量操作的处理范围。

翻译任务可以停止。已经得到的译文会直接写入当前工作区草稿，不生成备份；用户可以继续补齐剩余缺失项，也可以通过顶部按钮保存或保存并导表。翻译草稿按工作簿独立保存，切换项目或重新打开工具后可以恢复。

API 设置提供独立入口。工具复用现有 TCST 工具使用的 API 配置；新填写的密钥保存在 macOS 钥匙串中，不写入 README、工程配置或明文日志。只有用户主动发起翻译、一致性检查或连接测试时，工具才会调用已配置的服务。

### 6. 表格对比工作区

「表格对比」用于上线前比较一份历史版本目录和一份当前版本目录：

1. 选择历史版本配置表文件夹。
2. 选择当前版本配置表文件夹。
3. 工具按相对路径递归匹配两个文件夹中的表格。
4. 选择某个文件后查看完整配置表，并切换其中的工作表。
5. 按差异颜色、搜索和「已检查」进度逐项复核。

对比结果包含新增、删除、修改、相同和未完成几种状态。支持的比较类型为：

- `XLSX`、`XLSM`：比较全部工作表中的单元格值、类型和公式变化。
- `CSV`、`TSV`：比较表格数据，包含引号和跨行内容的处理。
- 可选按唯一 `ID` 或 `key` 对齐行；找不到可靠唯一键时会回退到按位置比较并给出提示。
- `XLS`、`ODS` 等当前不能完整解析的格式会标记为未完成，不会被误判为相同。
- 字体、配色等纯格式差异不作为数据差异。

差异展示遵循以下约定：

- 红色：删除；
- 绿色：新增；
- 紫色：修改；
- 修改单元格同时保留旧值和新值，便于确认具体变化；
- 有变化的行号格和列号格也会着色，不只给字母或数字文字上色；
- 搜索命中使用黄色边框提示；
- 选择表格后默认展示对应工作表的完整行列，而不是只列出差异单元格。

「标记已检查」会记录当前差异文件的复核状态，并在顶部和文件列表显示进度。它只统计需要复核的差异文件，不把相同文件算进未检查项。

对比表格使用按可视区域绘制的虚拟化渲染：完整数据仍保留并可滚动查看，但屏幕外的单元格不会一次性创建为大量界面对象。因此，即使修改条数很多，也不会因为把整张大表拆成数万个 UI 单元格而完全卡死；首次扫描和读取文件本身仍然会随数据量增加。

对比区支持：

- 触控板捏合缩放；
- 按住 `⌘` 或 `Control` 滚轮缩放；
- 顶部 `−`、当前比例、`+` 和「重置大小」按钮；
- 缩放范围 50%～250%；
- 切换文件或工作表时回到左上角；同一张表在缩放和搜索过程中保留当前视口；
- 导出完整 CSV 差异报告；
- 将新旧表打开到编辑工作区继续处理。

表格对比是只读操作，不会修改历史版本目录或当前版本源表。

## 工具构成

整体数据流可以概括为：

```text
Project 根目录
      │
      ▼
项目扫描、路径记忆与工程缓存
      │
      ▼
┌──────────────┬──────────────┬──────────────┬──────────────┐
│ 配置表工作区 │ 多语言工具   │ 导表日志     │ 表格对比工作区 │
│ 浏览/编辑    │ TbLanguage    │ Config/gen.sh│ 新旧文件夹     │
│ 多表并排     │ 翻译/检查    │ 实时输出      │ 全表差异       │
└──────────────┴──────────────┴──────────────┴──────────────┘
      │              │              │              │
      ▼              ▼              ▼              ▼
本地工作簿      语言表写回      工程导表脚本    历史/当前表格
```

### 源码模块

| 文件 | 职责 |
| --- | --- |
| `Sources/main.swift` | 应用主入口及基础能力；包含多语言工作簿读取、`TbLanguage` 解析、Shared Strings 与工作表 XML 处理、语言表写回、翻译服务调用、设置和导表相关逻辑。 |
| `Sources/WorkspaceShell.swift` | 工作区外壳；负责项目模型、项目 Tab、配置表目录、搜索和收藏、多表标签、并排布局、导表按钮、实时日志和退出前保存。 |
| `Sources/WorksheetWorkspace.swift` | 表格编辑引擎；负责单元格地址转换、XLSX 读写、ZIP/XML 处理、编辑、撤销/重做、行列选择、复制粘贴、冻结行列、外部变更检测、自动刷新和冲突保护。 |
| `Sources/FolderComparison.swift` | 文件夹比较引擎和显示层；负责递归扫描、表格匹配、工作表/单元格/公式差异、ID/key 对齐、检查进度、报告导出，以及虚拟化对比表格、差异颜色和缩放。 |
| `Sources/TranslationDraftStore.swift` | 多语言草稿本地存储；按工作簿保存和恢复翻译草稿，使应用重启后可以继续工作。 |
| `Sources/WorkspaceSmokeTests.swift` | 工作区回归测试；覆盖工作簿读写、特殊字符、外部修改保护、撤销、草稿恢复、递归对比、ID 对齐、公式变化和取消操作等。 |
| `Tools/render-icon.swift` | 用于构建时生成应用图标 PNG 和 ICNS 资源。 |
| `Tools/inspect-language-workbooks.mjs` | 辅助检查多语言工作簿结构。 |
| `build-app.sh` | 面向 Apple Silicon 编译应用、生成图标资源、复制 `Info.plist`、打包并进行本地签名。 |
| `Info.plist` | 应用名称、Bundle ID、版本号、最低系统版本和图标等应用元数据。 |

### 运行时边界

- 工具是原生 macOS 应用，目标架构为 Apple Silicon `arm64`。
- 工具直接读取本地工程和表格文件，不把源表上传到工具自身的服务器。
- 翻译和一致性检查只有在用户主动执行并配置 API 后才会调用外部服务；API Key 由 macOS 钥匙串保存。
- 导表的实际规则仍由各项目自己的 `Config/gen.sh` 决定；工具负责调度和展示日志。
- Git 提醒、Git 检查和 Git 拉取功能已经移除，工具不包含 Git 操作入口。
- 表格对比只读，不写入比较源目录。
- 保存和翻译写回源表前不会自动生成备份。

## 安装和启动

### 自动更新（1.6.0 起）

启动时和运行期间每 4 小时检查一次 GitHub 最新正式 Release。发现较新版本会弹出当前版本、新版本和发布说明，点击「安装并重启」下载更新。设置菜单提供「版本与更新说明」「检查更新」以及自动检查开关。自动检查失败时不打断工作，可手动检查查看错误。

安装前校验 GitHub 提供的 SHA-256、文件大小、应用标识、版本和签名完整性；有未保存表格、多语言修改或进行中的任务时阻止重启。安装会保留隐藏的上一版应用作为恢复副本（不是配置表备份），替换失败时尝试恢复旧应用。工程表格和用户设置不随应用包替换。应用目录必须可写；不能访问 GitHub 或无法替换时，可从发布页手动下载。当前使用本地签名，尚未经过 Apple 公证。

1.5.0 用户需要手动安装一次 1.6.0。后续发布须递增 `Info.plist` 的版本和 Build，创建匹配的 `vX.Y.Z` 正式 Release，填写更新说明，并附上 `DECT-macOS-arm64.zip`。仅提交源码不会触发客户端更新。该辅助检查脚本 `Tools/inspect-language-workbooks.mjs` 需要单独提供 `@oai/artifact-tool`，不参与应用构建。

1.6.2 修复安装后未重启的问题：替换后刷新应用注册，按明确路径启动新实例，并等待新应用的启动回执。助手就绪后才退出原应用；重启失败会打开安装日志，不再静默失败。恢复副本使用 `.backup` 后缀，避免作为同名应用被系统识别。旧版升级到 1.6.2 的这一次仍由旧更新器执行，如果没有自动打开，请从“应用程序”手动打开表格工具一次。

1.6.3 新增 Excel 风格右下角填充柄：支持文本复制、数字和日期序列、公式相对引用填充，并保留撤销/重做；填充范围限制为 50,000 个单元格，避免误拖造成界面卡顿。

正式应用包位于：

```text
/Applications/表格工具.app
```

可以将它拖入程序坞。首次使用时在工具内选择 `Project` 根目录；路径会被保存，后续可以直接进入上次使用的项目。

## 构建应用

在项目目录执行：

```sh
./build-app.sh
```

脚本会完成以下步骤：

1. 使用 Apple Silicon 和 macOS 14.0 目标编译 `Sources/*.swift`。
2. 生成应用图标的多尺寸 PNG 和 `AppIcon.icns`。
3. 复制 `Info.plist` 并生成 `dist/表格工具.app`。
4. 对应用包执行本地签名，并移除构建包的隔离属性。

构建前需要可用的 Apple 平台 Swift 编译环境和 `xcrun` 工具。构建产物默认位于：

```text
dist/表格工具.app
```

## 回归验证

项目提供独立的 smoke test 入口。测试使用临时副本，不应修改用户的源表。常用入口包括：

```text
--workspace-smoke <表路径...>
--comparison-smoke <xlsx路径>
--write-smoke
--batch-write-smoke
--wide-batch-write-smoke
--missing-translation-write-smoke
--content-import-smoke
```

工作区测试覆盖单元格写回、特殊字符、换行、Tab、引号、非目标内容保留、ZIP 完整性、外部修改保护、撤销和草稿恢复。对比测试覆盖子目录、全工作表、精准单元格差异、相同文件、CSV 引号跨行、新增、删除、ID 对齐、公式变化和取消操作。

如果需要手动编译 smoke test，可使用 `swiftc -D SMOKE_TEST` 编译 `Sources/*.swift`，再运行对应的入口参数。完整应用构建仍以 `./build-app.sh` 为准。

## 常见问题

### 找不到工程或项目列表为空

确认选择的是包含项目的 `Project` 根目录，而不是某个项目内部的 `Config` 目录。可以重新选择根目录并刷新项目清单。

### 导表失败并显示 `dotnet`、Luban 或文件不存在

工具已经把 `Config/gen.sh` 的原始输出和退出代码显示在日志中。此类错误通常来自项目自身的脚本依赖、相对路径、执行权限或本机运行环境，需要按日志中的具体路径处理；不需要打开 Unity 来重现导表流程。

### 两个项目有同名表，如何同时查看

开启多表并排，或通过「添加表格」分别打开两份完整路径不同的文件。工具按文件路径区分，不会因为文件名相同而互相覆盖。需要迁移配置时复制单元格、行或列即可。

### 为什么外部修改没有直接覆盖我的内容

这是冲突保护行为。表格存在未保存编辑时，工具会保留当前工作区内容并提示文件已经变化，避免外部刷新把本地修改静默冲掉。先保存或处理冲突，再继续刷新。

### 对比表很大时是否会卡死

对比界面采用可视区域虚拟绘制，屏幕外单元格不会全部创建为 UI 对象。大量数据仍会增加文件读取和差异计算时间，但不会因为一次性渲染整张表而创建同等数量的界面视图；如果需要可以使用停止操作中止当前比较。

### 对比颜色代表什么

红色是删除，绿色是新增，紫色是修改。行号格和列号格也会随对应区域着色；修改单元格会保留旧值与新值，便于确认改动方向。
